# ADR-013: Book state hash is defined through the concept
- Context: the replay check must show identical final state across runs and across book implementations.
- Decision: `state_hash` walks every locate and side through `for_each_level`/`for_each_order` and feeds price, quantity, count, id and FIFO position into FNV-1a 64; integers are mixed as fixed-width little-endian.
- Alternative rejected: hashing each implementation's internal memory.
- Why: internal layouts differ by design; a hash over the public view is equal exactly when the observable books are equal, including time priority.
- Consequence: a full hash costs 131,072 side visits, fine at end of replay but not per message; per-message checks use `symbol_hash` or snapshots.
