# ADR-005: Decoded messages are host-order structs passed to a typed handler
- Context: the parser, generator, encoder, oracle and tests all need one representation of each ITCH message.
- Decision: one plain struct per message type with host-order fields and the spec layout as `Offset` constants; the parser decodes into it and calls `handler.on(const T&)`, resolved at compile time.
- Alternative rejected: `#pragma pack` overlay structs read in place from the buffer.
- Why: overlays need byte swaps at every read and rely on unaligned access and type punning, which is undefined behaviour; a decoded struct of a few fields lives in registers.
- Consequence: the parser does one pass of byte swaps per message; `AnyMessage` (a std::variant) exists for tests and tools only and is not used on the hot path.
