# ADR-008: Valid edge cases and contract violations are separate scenarios
- Context: tests need both legal ITCH corner cases (full executions, levels emptying) and inputs a real exchange never sends (unknown ids, zero quantities).
- Decision: three generators: `generate_random` and `generate_edge_cases` emit only valid ITCH; `generate_contract_violations` emits the invalid inputs the book contract defines.
- Alternative rejected: one mixed edge-case feed.
- Why: a valid feed can be checked by a simple validity replay, and an invalid input in it would hide behind the contract's no-op rules.
- Consequence: valid feeds are asserted valid in tests; the violations feed is asserted invalid and exercised only against the contract.
