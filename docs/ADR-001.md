# ADR-001: CMake presets as the single build entry point
- Context: four build flavours (debug, release, asan+ubsan, tsan) must be reproducible locally, in CI and on the benchmark host.
- Decision: CMake >= 3.25 + Ninja, one configure/build/test preset per flavour, plus `release-gcc` and `fuzz`; clang is the default compiler.
- Alternative rejected: toolchain files or a Makefile wrapper selecting flags by hand.
- Why: presets are versioned with the code, so CI and RUN_BENCH.md run the same command a reader would.
- Consequence: build directories are `build/<preset>`; adding a flavour means adding a preset, not editing scripts.
