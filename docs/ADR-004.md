# ADR-004: Test labels separate infrastructure from owner-written code
- Context: the parser, the two fast books and the risk check start as failing stubs, yet CI must still prove the rest of the project works.
- Decision: every test carries the ctest label `infra` (must pass) or `owner` (tests the hand-written hot path, failing until implemented).
- Alternative rejected: disabling owner tests or marking them as expected failures.
- Why: the owner tests stay live and visible; a stub that starts passing is noticed immediately, nothing is hidden.
- Consequence: CI gates on `ctest -L infra`; `ctest -L owner` runs and reports but does not gate until the owner flips it.
