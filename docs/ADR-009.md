# ADR-009: Fault injector keeps original sequence numbers
- Context: gap handling must be tested against drops, duplicates and reordering, but the sample-file framing has no sequence numbers.
- Decision: number messages 1..n, then drop, duplicate and delay messages by up to N positions while each message keeps its original number.
- Alternative rejected: corrupting the byte stream directly.
- Why: a consumer sees exactly what it would see on MoldUDP64 (gap, repeat, late arrival), and tests can tell which fault caused which state difference.
- Consequence: the gap-policy harness consumes `Sequenced` messages; fault runs are deterministic for a given seed.
