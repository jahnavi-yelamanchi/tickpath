# ADR-014: Parser skips unknown types by frame length and resumes by offset
- Context: Nasdaq adds message types over time (h and O arrived after 5.0's first release), and file or socket reads end mid-frame.
- Decision: `parse_frames` skips frames with an unknown type and counts them; on an incomplete trailing frame it returns Truncated with `consumed` at that frame's start; a known type with the wrong frame length stops with LengthMismatch.
- Alternative rejected: failing on any unknown type, or treating a short tail as an error.
- Why: the length prefix makes skipping safe, and a resume offset lets the same function serve mmap replay and chunked reads.
- Consequence: a corrupt length that lands on a known type is caught by the spec-length check; one that lands on an unknown type is skipped silently and must be caught downstream (book statuses).
