# ADR-018: Golden replay hash taken from the oracle
- Context: the deterministic replay check needs an expected value that does not come from the code under test.
- Decision: the golden hash is the oracle's final state hash for a fixed generated day (seed 20261119, 50,000 order messages, 16 symbols), applied as typed messages without the parser; every book, through the parser, must reproduce it twice in a row.
- Alternative rejected: recording the hash from the first fast-book run.
- Why: a value taken from the code under test would pin its bugs; the oracle path shares no code with the parser or the fast books.
- Consequence: a deliberate change to the generator, encoder or book contract requires updating `tests/replay/golden.hpp` in the same commit, with the reason.
