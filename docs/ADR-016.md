# ADR-016: Owner-written parts start as compiling stubs returning NotImplemented
- Context: the parser, the two fast books and the risk check are written by the owner; everything around them must build and run first.
- Decision: each has a header with the final interface and bodies that return `NotImplemented`, empty optionals or zero; they are instantiated in a clang-tidy-checked TU.
- Alternative rejected: declarations without definitions (link errors) or `static_assert(false)` bodies.
- Why: the full build, sanitizers and every harness work from day one; the owner tests fail at runtime with a clear status instead of the build failing.
- Consequence: `NOLINT` markers and `OWNER: implement` comments in the stubs are deleted with the stub bodies.
