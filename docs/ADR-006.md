# ADR-006: Input unit is the sample-file frame (2-byte length + message)
- Context: ITCH arrives over MoldUDP64 live, but the public sample days use a simpler file framing.
- Decision: the parser consumes `[u16 big-endian length][message]` frames; the generator writes the same framing.
- Alternative rejected: modelling MoldUDP64 packets (session, sequence number, message count) in the input.
- Why: the benchmark replays sample files, and MoldUDP64 adds nothing to parser or book correctness.
- Consequence: sequence numbers for gap tests are assigned by the fault-injection harness, one per message, as MoldUDP64 would.
