# ADR-010: One market-wide book behind a compile-time concept
- Context: three book implementations (oracle, flat array, tree) must be interchangeable in tests and benchmarks without runtime dispatch cost.
- Decision: `OrderBook` is a C++20 concept over a market-wide book (all locates, one order index); code is templated on the book type.
- Alternative rejected: an abstract base class with virtual methods, or one book object per symbol.
- Why: virtual calls block inlining on the hot path; ITCH execute/cancel/delete carry only the order id, so a per-symbol book still needs a global id index.
- Consequence: every harness is a template; a new book is checked by `static_assert(OrderBook<T>)` and gets every test by adding it to a type list.
