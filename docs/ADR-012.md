# ADR-012: The oracle stores no derived state
- Context: the reference book is trusted to judge the fast books, so its own bugs must be implausible.
- Decision: `ReferenceBook` stores only orders and per-level FIFO id vectors in std::map; level quantity and count are recomputed from orders on every query.
- Alternative rejected: caching level aggregates, as the fast books will.
- Why: a cache can drift from the orders it summarises; recomputing removes that class of bug from the oracle.
- Consequence: the oracle is slow (O(level size) per query) and allocates; it is used only in tests, tools and as a benchmark baseline.
