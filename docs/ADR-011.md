# ADR-011: Inconsistent input is a no-op with a status, except overfill
- Context: under drops and duplicates a book sees unknown ids, duplicate ids, zero quantities and executions larger than the order.
- Decision: such operations return a Status and leave the book unchanged; an execute or cancel above the remaining size removes the order and returns Overfill (docs/BOOK_CONTRACT.md).
- Alternative rejected: asserting/aborting, or clamping overfills to leave a zero-share order.
- Why: a feed handler must survive bad input and report it; the exchange has already removed an overfilled order, so keeping it would leave a phantom level.
- Consequence: every book needs the same check order; the contract tests pin the precedence, and the gap-policy harness uses the statuses as evidence of damage.
